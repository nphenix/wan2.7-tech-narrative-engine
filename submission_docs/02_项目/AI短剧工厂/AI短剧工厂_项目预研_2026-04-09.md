# AI短剧工厂项目预研

- 文档状态：预研阶段
- 适用范围：面向以 AI Agent 产品服务 AI短剧工厂的项目分析
- 更新时间：2026-04-09

## 一、项目背景与预研目标

本项目当前预研的对象，不是“AI短剧工厂”这个业务概念本身，而是：

`一个通过 AI Agent 产品能力，服务 AI短剧工厂创作、生产与资产沉淀全流程的基础设施型产品。`

这意味着预研问题不应停留在“AI 能不能写短剧”或“短剧工厂应该长什么样”，而应集中回答以下问题：

- AI短剧工厂在真实业务中最痛的环节是什么
- AI Agent 产品应该提供哪些关键能力去承接这些痛点
- 产品能力应该如何分层，才能既满足创作，又支撑规模化生产和长期沉淀

基于当前项目目标，本文将预研内容统一组织为三条核心链路：

1. `创作中枢`
2. `自动化生产工厂`
3. `知识资产沉淀管理`

## 二、预研判断与总体结论

结合你的明确要求、当前业务目标、行业公开反馈以及对 Agent 产品组织方式的综合判断，本项目当前可以先得出以下结论。

### 1. 项目成立的关键，不是“能不能生成短剧”，而是“能不能把短剧业务组织成稳定系统”

从现有行业实践看，生成剧情、脚本、分镜建议乃至视频片段已经不是最稀缺的能力。真正让团队持续遇到问题的，是：

- 方向反复变化
- 角色和世界观不断漂移
- 从创意到脚本再到分镜的链路割裂
- 批量生产时质量波动大
- 每次项目结束后经验无法复用

因此，项目成立前提不是再做一个“更强的生成器”，而是做一个能把短剧创作、生产、复盘组织起来的 Agent 产品。

### 2. 产品不能按散点功能描述，必须按三条核心链路建模

如果只按“脚本生成、分镜生成、评分、资产管理”罗列功能，最后容易写成工具堆砌，无法形成项目主线。

更合理的产品结构，应当是：

1. `创作中枢`
负责把需求、策划、人设、剧情、脚本、审阅组织成一条可控创作链路。

2. `自动化生产工厂`
负责把已经可控的创作结果，推向批量化、标准化、可调度的生产流程。

3. `知识资产沉淀管理`
负责把角色、场景、模板、规则、案例、修改记录和复盘知识持续回流，形成长期资产底座。

### 3. 三条链路不是并列拼盘，而是前后相扣的系统骨架

三条链路各自解决不同问题：

- 创作中枢：解决“怎么把创作组织起来”
- 自动化生产工厂：解决“怎么把组织好的创作规模化生产”
- 知识资产沉淀管理：解决“怎么让系统越做越强”

同时三者又存在明确依赖关系：

- 没有创作中枢，生产工厂没有稳定输入
- 没有生产工厂，创作中枢难以支撑规模化交付
- 没有知识资产沉淀管理，前两者难以形成复利和壁垒

因此，当前项目不应被理解为单点生成工具，而应被理解为：

`服务 AI短剧工厂的 Agent 化创作与生产基础设施。`

## 三、AI短剧工厂当前核心痛点

围绕短剧工厂的真实工作流，当前主要痛点可归纳为以下七类。

### 1. 选题与方向判断不稳定

短剧项目通常需要快速判断题材方向、平台适配、受众吸引力和商业目标承接能力，但很多团队仍然依赖人工反复碰撞，成本高、结论慢、试错重。

### 2. 人设、世界观与剧情规则容易漂移

随着多轮迭代推进，角色语言风格、人物动机、关系逻辑、世界观约束经常发生漂移，导致后续脚本和分镜不稳定。

### 3. 从创意到脚本再到分镜的链路断裂

很多团队能产出创意，也能写剧本，但很难把这些内容持续转化成适合生产执行的分集结构、场次结构和分镜结构。

### 4. 批量生产效率低，调度能力弱

一旦进入多项目并行、多版本并行、多平台适配，团队会迅速遇到任务调度混乱、版本混乱、状态不可见的问题。

### 5. 高价值质量判断集中在核心人员，缺少有效放大机制

什么叫节奏好、钩子强、反转有效、品牌不出戏、角色可演，这些判断本来就应该由资深编导或策划主导。这不是问题本身，问题在于当前系统往往缺少足够好的辅助机制去放大他们的能力，例如：

- 没有把他们的判断标准结构化沉淀下来
- 没有把他们从重复比对、重复校审里解放出来
- 没有让他们把时间集中在高价值判断和关键取舍上

因此，本项目不应试图取代核心人员，而应通过 Agent 工作流帮助他们更高效地发挥专业能力、覆盖更多项目并沉淀更多组织价值。

### 6. 资产管理弱，难以复用

角色卡、场景设定、服化道设定、镜头模板、剧情模板、品牌表达规则等往往散落在多个文档、表格和聊天记录中。

### 7. 项目结果无法沉淀为长期资产

很多短剧项目完成后，只留下若干成片或脚本，没有沉淀为后续项目可直接调用的知识资产，导致下一次又从头开始。

## 四、项目定位

本项目建议定位为：

`一个面向 AI短剧工厂的 AI Agent 产品，以创作中枢、自动化生产工厂、知识资产沉淀管理三条核心链路组织能力，服务短剧从创作到生产再到资产回流的完整业务闭环。`

该定位强调四点：

- 服务对象是 AI短剧工厂，而不是泛内容创作者
- 产品核心是 Agent 化流程能力，而不是单模型炫技
- 项目目标是稳定交付和规模化生产，而不是偶发高光生成
- 人工主控权必须保留在关键创作节点

## 五、核心链路一：创作中枢

创作中枢是短剧工厂的前端大脑，负责把原本离散的创意、策划、编剧和审阅流程组织起来。它解决的是“创作如何可控地启动、推进和收口”。

### 1. 创作中枢要承接的核心问题

- 需求是否被正确理解
- 方向是否足够清晰
- 人设和世界观是否稳定
- 剧情和脚本是否持续可控
- 人工审阅是否有明确抓手

### 2. 创作中枢建议覆盖的核心能力

- 创作需求理解与任务编排
- 选题策划与方向判断
- 角色设定与世界观管理
- 故事设计与分集规划
- 脚本与台词生成
- 一致性检查
- 人工审阅、版本比对与修改留痕

### 3. 创作中枢的关键工作节点

从业务上看，创作中枢至少包含以下关键工作节点：

- 需求理解
- 选题策划
- 人设设定
- 剧情规划
- 脚本生成
- 一致性检查
- 审阅辅助

这些节点首先是工作节点，而不是先验成立的 Agent 角色。是否需要拆成多个 Agent，应该建立在实现评估而不是命名直觉之上。

### 4. 创作中枢的实现方式评估原则

在系统设计阶段，建议围绕以下问题评估每个节点更适合采用“多 Agent 拆分”还是“单 Agent 调用不同 skills”：

- 该节点由谁参与
- 输入是什么
- 输出是什么
- 是否需要长期状态保持
- 是否需要明确责任边界
- 是否需要和上下游频繁交接
- 多 Agent 之间的上下文传递成本是否过高
- 单 Agent 调用不同 skills 的上下文切换成本是否更低

基于当前预研判断，创作中枢早期更适合优先采用：

`单创作主 Agent + 多个 skills`

原因在于需求理解、选题策划、人设设定和剧情规划之间存在大量强耦合的隐式上下文，如果过早拆成多个 Agent，容易带来高额的上下文传递成本和语义损耗。

而脚本生成、一致性检查、审阅辅助等节点，由于输入输出边界更容易结构化，后续可以根据实际运行效果逐步独立为专门 Agent。

因此，创作中枢在预研阶段不宜先写死为“七个并列 Agent”，而应保留为：

`关键工作节点已明确，具体采用单 Agent + skills 还是多 Agent 拆分，留待设计阶段结合上下文传递成本、职责边界和状态管理要求再做定型。`

### 5. 创作中枢的价值判断

创作中枢不是一个单点工具，而是整个系统的控制层。没有这一层，后续生产环节就会缺少稳定输入、统一口径和可追踪上下文。

## 六、核心链路二：自动化生产工厂

自动化生产工厂是短剧工厂的执行层。它的核心职责不是继续参与创作判断，而是承接创作中枢已经形成并经过确认的结果，把这些结果转化为生产系统里的执行对象，并组织后续批量化、标准化、可追踪的执行流程。

因此，这一链路解决的不是“怎么创作”，而是：

- 如何接住创作结果
- 如何把创作结果转成生产任务
- 如何让生产过程可调度、可追踪、可筛选、可回退
- 如何让生产结果继续回流知识资产层

### 1. 自动化生产工厂的承接输入

自动化生产工厂不应直接承接模糊创意或半成品判断，而应承接已经由创作中枢相对稳定下来的结果，例如：

- 已确认的选题方向
- 已确认的人设与世界观约束
- 已确认的分集结构
- 已审核的脚本版本
- 已形成的分镜草案或镜头任务
- 已绑定的角色、场景、服化道和风格规则

这些内容一旦进入自动化生产工厂，就不再是“讨论对象”，而是“执行对象”。

### 2. 自动化生产工厂要承接的核心问题

- 如何把脚本稳定拆成分镜与生产单元
- 如何把角色、场景、服化道等资产绑定进生产流程
- 如何支持多项目并行、多版本并行和状态追踪
- 如何对批量结果做快速评分、筛选和回退

### 3. 自动化生产工厂建议覆盖的核心能力

- 分镜拆解与镜头规划
- 资产绑定与批量调用
- 任务调度与状态追踪
- 多项目并行管理
- 质量评审与批量评分
- 生产异常回退与补偿

这些能力可以进一步理解为三类：

- `执行对象转换能力`
  把脚本、设定、分镜草案转成可执行任务单、批处理单元和调度对象
- `生产编排能力`
  负责任务拆分、资源绑定、队列调度、状态流转、异常回退
- `结果筛选能力`
  负责批量评分、快速筛选、保留优选结果，并将结果送往交付或回流环节

### 4. 自动化生产工厂的输出对象

自动化生产工厂完成处理后，应输出的不是新的创意结论，而是可交付、可追踪、可继续复用的生产结果，例如：

- 可执行任务单
- 批量生产队列
- 生产状态面板
- 质量评分结果
- 筛选后的候选结果
- 异常回退和补产指令

这也意味着，自动化生产工厂与创作中枢最大的差异，不在“谁更强”，而在“处理对象不同”：

- 创作中枢处理的是创作问题
- 自动化生产工厂处理的是生产对象

### 5. 自动化生产工厂对应的实现角色

- 分镜设计 Agent
- 资产绑定 Agent
- 调度控制 Agent
- 批量评审 Agent
- 结果筛选 Agent

这里同样不宜过早把它们写死为并列独立 Agent。更稳妥的做法是：

- 先明确这些执行角色在生产链路中的职责
- 再在设计阶段评估哪些适合独立 Agent，哪些适合由调度主 Agent 调用不同 skills 完成

因为自动化生产工厂虽然比创作中枢更容易结构化，但同样存在上下文传递成本、调度成本和状态同步成本。

### 6. 自动化生产工厂的价值判断

自动化生产工厂不是对创作中枢的替代，也不是简单对前者做能力放大，而是承接创作中枢已经形成的结果，并把这些结果转化为生产系统中的执行对象。更准确地说：

- 创作中枢负责形成高质量、可审阅、可确认的创作结果
- 自动化生产工厂负责接住这些结果，并把它们转成可调度、可批量、可跟踪、可回退的执行流程

没有创作中枢，自动化生产工厂会缺少稳定输入；没有自动化生产工厂，创作结果就难以进入规模化生产与交付阶段。

## 七、核心链路三：知识资产沉淀管理

知识资产沉淀管理是短剧工厂的长期底座，负责把每次创作和生产过程中产生的有效规则、模板、案例和修改经验沉淀下来。它解决的是“系统如何越做越强，而不是每轮重新开始”。

### 1. 知识资产沉淀管理要承接的核心问题

- 角色和世界观规则如何长期复用
- 场景、服化道、镜头模板如何反复调用
- 高表现剧情结构如何回流为标准模板
- 修改记录和复盘结论如何进入下一轮生产

### 2. 知识资产沉淀管理应具备的产品构建能力

在预研阶段，这一链路不宜先预设“要建哪些库”，因为不同团队、不同项目阶段、不同组织习惯下，真正值得沉淀的资产类型并不完全相同，应该保留与用户共创规划的空间。

因此，这里更应该从产品构建角度定义能力，而不是先列资产目录。建议产品至少具备以下构建能力：

- 资产采集能力
  能从创作过程、生产过程、审阅过程和交付结果中持续采集可沉淀对象，而不是只接受人工上传。
- 资产结构化能力
  能把原始内容拆解成可标注、可分类、可追踪、可复用的结构化单元。
- 资产治理能力
  能支持标签体系、版本管理、引用关系、状态管理和质量校验。
- 资产回流能力
  能把沉淀结果回流到创作中枢和自动化生产工厂，真正参与下一轮生产，而不是静态存档。
- 资产推荐能力
  能在合适节点向用户和系统推荐可复用资产，提高命中率和复用效率。
- 权限与边界控制能力
  能控制哪些资产对哪些角色开放，避免核心方法、模板和素材被无序扩散。
- 共创规划能力
  能支持系统方与用户一起逐步定义“哪些内容值得沉淀、如何分类、如何命名、如何调用”，而不是由产品方单方面预设完毕。

也就是说，产品要先解决“怎么构建知识资产沉淀体系”，而不是在预研阶段先替用户决定“最终一定有哪些库”。

### 3. 知识资产沉淀管理对应的实现角色

- 资产整理 Agent
- 模板沉淀 Agent
- 复盘归纳 Agent
- 案例推荐 Agent

### 4. 知识资产沉淀管理的价值判断

这条链路不是附加项，而是三条链路里最容易被低估、却最决定长期壁垒的一条。它既支撑创作中枢，也持续反哺自动化生产工厂。

## 八、三条核心链路之间的关系

为了避免把系统理解成三个彼此孤立的功能块，必须明确三者虽然是并列模块，但在业务流转上存在清晰衔接关系。

### 1. 创作中枢

创作中枢是一个独立模块，负责形成结构化创作结果，组织需求理解、方向判断、人设设定、剧情规划、脚本生成和人工审阅。

### 2. 自动化生产工厂

自动化生产工厂是一个独立模块，负责承接创作中枢已经形成并确认的结果，并将其转化为可调度、可批量、可追踪、可回退的生产执行对象。

### 3. 知识资产沉淀管理

知识资产沉淀管理是一个独立模块，负责对创作与生产过程中形成的有效对象进行采集、治理、回流和复用。

因此，更准确的系统理解应该是：

- 三者在产品结构上是并列模块
- 创作中枢向自动化生产工厂输出结构化创作结果
- 创作中枢与自动化生产工厂共同向知识资产沉淀管理提供沉淀对象
- 知识资产沉淀管理再向前两者回流可复用资产与治理结果

## 九、产品边界判断

### 当前纳入范围

- 创作中枢能力
- 自动化生产工厂能力
- 知识资产沉淀管理能力

### 当前暂不纳入范围

- 完整视频成片平台
- 泛内容分发平台
- 投流投放系统
- 完整后期剪辑系统
- 长篇影视工业化平台

当前项目边界应聚焦在“服务 AI短剧工厂的 Agent 产品”，而不是一次覆盖整条短剧产业链。

## 十、阶段化建设建议

### 第一阶段：优先建立创作中枢

重点建设：

- 需求理解
- 选题策划
- 人设与世界观管理
- 分集规划
- 脚本生成
- 一致性校验
- 人工审阅

并同步启动最基础的知识资产沉淀管理：

- 资产采集机制
- 基础标注与分类规则
- 修改记录留痕
- 用户共创定义机制

### 第二阶段：扩展自动化生产工厂

在第一阶段稳定后，继续补齐：

- 分镜拆解与镜头规划
- 资产绑定与批量调用
- 多项目并行调度
- 生产状态追踪
- 批量质量评分
- 结果筛选与回退

### 第三条持续主线：持续强化知识资产沉淀管理

它不应在末期补做，而应从第一阶段开始就持续建设、持续回流、持续强化。

## 十一、初步建设目标

### 1. 流程目标

把短剧工厂的创作和生产流程组织成可重复运行的 Agent 工作流。

### 2. 质量目标

让创作结果更稳定、更可控，让生产结果更可筛选、更可回退。

### 3. 协同目标

让策划、编剧、导演、运营等角色在同一链路中协作、审阅和留痕。

### 4. 资产目标

让每次创作和生产结果都能回流为角色资产、剧情模板、分镜规则和复盘知识。

## 十二、阶段性判断

综合当前分析，本项目具备继续推进的条件，原因如下：

- AI短剧工厂的痛点已经足够清晰，并且适合按三条链路拆分
- 创作中枢、自动化生产工厂、知识资产沉淀管理三者之间的关系已经可以明确建模
- Agent 化分工、人工主控和资产底座具备明确产品价值
- 项目可以先从创作中枢切入，再扩展到自动化生产工厂，并持续强化知识资产沉淀管理

因此，当前建议将本项目作为 `ai_project_2033` 阶段的正式预研产物，并进入 `ai_project_2033/ceo_review`，进一步校准范围姿态与阶段节奏，再决定是否进入 `ai_design_2033`。
